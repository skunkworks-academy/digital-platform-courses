# Security and Governance

**Outcome:** Threat-model a repository and apply controls that prevent, detect, and respond to common software-supply-chain risks.

Start with identity: require MFA, prefer enterprise-managed access where appropriate, use teams and least privilege, review outside collaborators, and remove stale access. Protect critical branches with review and status requirements while controlling bypass rights.

Repository security is layered:

- **Secrets:** never commit them; use secret scanning and push protection where available; rotate immediately if exposed.
- **Dependencies:** maintain a dependency graph, review new transitive risk, enable alerts and controlled updates.
- **Code:** use code scanning where supported and triage findings by reachability, severity, and business context.
- **Workflows:** minimize token permissions, pin trusted actions, constrain untrusted input, and protect deployment environments.
- **Response:** publish `SECURITY.md`; handle vulnerabilities privately; preserve evidence and document remediation.

Plan and license availability differ. If a feature is unavailable, record the gap and implement a proportional alternative such as local scanning, manual dependency review, or an external approved control.
