# GitHub Course Guide

## Audience and prerequisites

This course is for developers, analysts, technical writers, administrators, and project contributors who need a dependable GitHub workflow. No prior GitHub experience is required. You need a GitHub account, a modern browser, Git 2.40+ and a text editor. Command-line alternatives are shown; GitHub Desktop is acceptable when it produces equivalent evidence.

## Safe setup

Create a private or public practice repository named `delivery-practice`. Do not commit passwords, tokens, `.env` files, customer data, proprietary source, or signing keys. Turn on multi-factor authentication for your account. Where an organization policy prevents a task, document the restriction and complete the equivalent activity in a personal sandbox.

## Assessment blueprint

| Outcome | Formative evidence | Summative evidence |
|---|---|---|
| Repository and Git concepts | Module checks, history inspection | Explain repository state and recover a safe change |
| Collaboration | Branch/PR lab | Traceable issue-to-PR workflow with review |
| Automation | Actions lab | Passing CI workflow and failure diagnosis |
| Security/governance | Security checklist | Least-privilege settings and risk rationale |
| Release | Release exercise | Tagged, documented release and evidence pack |

Completion requires 80% on the knowledge check and at least 70/100 on the capstone, including every critical security criterion. See the shared assessment policy for retakes and appeals.
