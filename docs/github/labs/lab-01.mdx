# Lab 1 — Governed Repository

**Time:** 40 minutes · **Environment:** disposable GitHub repository

## Brief

Your team is starting a small public documentation tool. Create a repository that a new contributor can understand and that a maintainer can govern safely.

## Tasks

1. Create the repository with a description and intentional visibility choice.
2. Add `README.md`, `CONTRIBUTING.md`, `SECURITY.md`, `.gitignore`, and `CODEOWNERS`.
3. Create labels for defect, enhancement, documentation, and security-sensitive work.
4. Add an issue form with problem, acceptance criteria, risk, and validation fields.
5. Configure a ruleset or document the exact rule you would apply: PR required, one approval, conversation resolution, and a named status check.
6. Invite a collaborator only if safe; otherwise explain the required role.

<div className="evidence"><strong>Evidence:</strong> repository tree, anonymized rules summary, completed sample issue, and a 150-word least-privilege rationale. Never submit private URLs or identities unnecessarily.</div>

## Success check

A stranger can identify purpose and contribution path; a vulnerability has a private reporting route; the default branch is not directly writable by ordinary contributors; no secret exists in history.
