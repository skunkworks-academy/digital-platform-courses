# Lab 2 — Issue-to-PR Collaboration

**Time:** 50 minutes

Create an issue requiring a documentation validation script. Include at least three testable acceptance criteria. Create a branch, implement a minimal script or documentation change, and make two coherent commits. Open a pull request that links and closes the issue.

Self-review the diff. Ask a peer to leave one substantive comment, or simulate the reviewer role in a second pass and label it clearly. Respond with evidence, update the change, rerun validation, and merge under the repository policy.

Induce a safe conflict by editing the same harmless sentence on two branches. Resolve it by retaining the intended meaning from both changes and record the validation performed after resolution.

<div className="evidence"><strong>Evidence:</strong> issue acceptance criteria, commit graph, PR description, substantive review exchange, conflict-resolution diff, passing checks, and final merged commit.</div>

## Reflection

Which activity found the most important defect: acceptance criteria, self-review, human review, or automation? Explain what should change in your next workflow.
