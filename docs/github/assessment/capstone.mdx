# GitHub Capstone — From Intake to Release

## Scenario

You own delivery for a small web service. A sponsor asks for a health endpoint and updated operating guidance. The change must be reviewable, automatically validated, safely releasable, and recoverable.

## Deliverables

1. A repository charter and threat-aware governance configuration.
2. An issue with stakeholder need, scope, constraints, acceptance criteria, and test plan.
3. A branch with coherent commits and no sensitive data.
4. A pull request with traceability, risk, test evidence, and rollback plan.
5. At least one substantive review finding and a verified resolution.
6. A least-privilege CI workflow with one deliberately diagnosed failure and a final passing run.
7. A security posture summary covering identities, secrets, dependencies, code and workflows.
8. A versioned release with release notes and an evidence index.
9. A 300-word retrospective proposing one measurable improvement experiment.

## Conditions

Complete in a disposable repository. You may consult official documentation and declare assistance. Do not use real secrets or production resources. Estimated effort: 90 minutes after labs.

Submit a redacted evidence index that maps each rubric criterion to an immutable link, file, commit, or exported record. The assessor may ask you to explain any two decisions live or in writing.
