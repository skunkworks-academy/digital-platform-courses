# Module 5: Home Wi-Fi, websites and safe connectivity

**Learning time:** 45–60 minutes. **Outcome:** understand and apply this protective capability in an authorised home or small-business setting.

## Understand the threat and control

A router connects local devices to the internet. WPA2-AES or WPA3 protects Wi-Fi traffic; strong unique router admin credentials and firmware updates matter. Guest networks reduce unnecessary internal exposure. HTTPS protects transport to a site, but a fraudulent site can also use HTTPS. DNS helps translate names into addresses; browser warnings and domain spellings require attention. Public Wi-Fi needs caution, and a VPN is not a substitute for authenticating websites and users.

## Practical case

A home office shares one Wi-Fi password with temporary visitors and accounting computers. Propose a guest network, router update window, admin access policy and device inventory.

## Guided exercise

1. Sketch a network diagram with router, work devices, guest network and cloud services. Label trust boundaries and where MFA is enforced.
2. Create a simple table with **risk, evidence, control, owner and review date**.
3. Model a successful authorised action and an unauthorised or failed action; explain how the control responds.
4. Record observations, assumptions and recommended next steps separately.

## Avoid these mistakes

Compare a correct website address with a lookalike in a fictional example and record the safest response.

## Knowledge checkpoint

1. Explain the primary control and the harm it reduces.
2. What evidence would prove the control worked, and what would trigger escalation?

## Extended learning: distinguish safe connections from trusted services

Home or office Wi-Fi security requires **an approved router configuration, strong administrative access, appropriate encryption and ongoing firmware updates**. WPA2-AES or WPA3 are common secure options where supported; open networks and obsolete encryption provide weaker protection. Guest networks reduce unnecessary device-to-device reachability, but a guest network alone is not proof of isolation.

### Worked example: a small training centre

The centre has staff laptops, learner Wi-Fi and a network printer.

1. Draw a simple diagram: internet connection → router/firewall → separate staff and learner networks.
2. Define which devices may use the printer and which must not access staff files.
3. Protect router administration with a unique password and up-to-date configuration.
4. Specify the expected outcome for a legitimate staff print job.
5. Specify a **denied** learner-to-staff resource connection and a safe verification method.
6. Document any settings requiring an authorised network administrator.

### Compare three kinds of safety

| Feature | Helps with | Does not prove |
|---|---|---|
| HTTPS | Encrypts transport to the connected website | The website or seller is honest |
| Wi-Fi password | Restricts association to a wireless network | Every connected device is safe |
| Firewall policy | Allows or blocks defined network traffic | An allowed application is harmless |

**Practice:** Given a fictional public Wi-Fi login page requesting payment-card details, identify how you would independently confirm it is genuine before entering information. Never probe a real network you do not own or administer.
