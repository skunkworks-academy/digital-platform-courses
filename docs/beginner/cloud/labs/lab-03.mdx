# Lab 3: Secure deployment and incident tabletop

**Duration:** 90 minutes. **Mode:** no-charge cloud simulation or authorised sandbox.

## Scenario

A small business deploys a new cloud web app and encounters a simulated service outage.

## Hands-on lab procedure

1. Create a change ticket, owner list and low-risk release window.
2. Prepare a least-privilege access matrix and two deny tests.
3. Specify deployment validation for HTTPS, app health, static assets and database connection.
4. Simulate a configuration fault leading to partial outage and create a structured event timeline.
5. Select monitoring signals, support escalation and a safe rollback decision.
6. Document a restore drill or an equivalent recovery simulation.
7. Deliver an incident report and a post-incident action list.

## Acceptance criterion

The learner demonstrates secure staging, deterministic incident response and restored service without privileged shortcuts.

Provide: a scope statement, a labelled diagram or cost workbook, redacted evidence for each key design decision, one positive and one deliberately invalid/denied test, and 100–150 words of lessons learned. For failures, record the hypothesis, observed result, corrective action and safe rollback.

:::warning Safe cloud practice
Do not use production resources, real credentials or chargeable cloud services without written approval. A detailed spreadsheet or architecture simulation is a valid lab path.
:::
