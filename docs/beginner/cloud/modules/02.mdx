# Module 2: IaaS, PaaS, SaaS and shared responsibility

**Suggested time:** 45–70 minutes. **Competency:** The service comparison assigns responsibilities correctly and recommends a service on measurable needs.

## Concepts and architecture

Infrastructure as a Service (IaaS) exposes virtual computing, storage and networking while customers configure operating systems and applications. Platform as a Service (PaaS) delegates more of the underlying platform operations, letting customers focus on applications and data. Software as a Service (SaaS) delivers ready-to-use applications with customer responsibilities for users, information and configuration. Managed databases and serverless functions illustrate a spectrum of responsibilities, not a guarantee of no management. The shared-responsibility model divides duties according to services and agreements: providers secure underlying infrastructure, while customers must still classify data, manage users, select configurations, protect credentials and plan recovery.

## Workplace scenario

A business chooses between hosting a customer database on a virtual machine, using a managed SQL database or subscribing to an online CRM. For each, identify who patches the OS, backs up application data and controls user accounts.

## Applied exercise

1. Create a three-column IaaS/PaaS/SaaS table with one realistic example per column.
2. For each example, assign ownership of hardware, guest OS, runtime, access control, backup and application data.
3. Identify a duty that remains with the customer in all three models.
4. Select the service model best suited to a small team without dedicated system administrators, explaining trade-offs.
5. List contract questions about service-level agreements, data export, retention and incident reporting.

## Validation and reflection

The service comparison assigns responsibilities correctly and recommends a service on measurable needs. Create a verification register with **expected state**, **observed state**, **evidence**, **risk**, **owner** and **follow-up**. At least one test must demonstrate permitted activity and another must show an improper action is blocked or a faulty assumption is detected. Do not perform tests on systems without permission.

### Review questions

2. Why does PaaS not remove responsibility for data protection?
