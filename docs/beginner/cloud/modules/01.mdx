# Module 1: Cloud services and how they work

**Time:** 50–70 minutes. **Learning criterion:** The comparison reflects cost and operational trade-offs, identifies a decision owner and lists any information still needed.

## Understand the concepts

Cloud computing offers shared pools of configurable computing resources over a network. Common characteristics are on-demand self-service, broad network access, resource pooling, rapid elasticity and measured service. Renting capacity can shorten the time to experiment, but responsibility for design, billing, data and access remains. Cloud services depend on network access and provider operations; they are neither automatically inexpensive nor immune to failure. Contrast a physical server, a hosted virtual machine, a managed application and an Internet-delivered file service.

## Workplace example

A local training agency sees large spikes in learner registrations twice yearly. It needs short-term capacity without purchasing hardware used for only a few weeks.

## Guided practical activity

1. Explain the five defining cloud characteristics in plain language.
2. Build a comparison table for owning a small server and purchasing hosted capacity: hardware, support, security, connectivity, speed and cost.
3. Write three reasons the agency might use cloud services and two situations where an on-site workload could still be suitable.
4. Record one measurable criterion for evaluating the proposed migration.

## Confirm the learning

The comparison reflects cost and operational trade-offs, identifies a decision owner and lists any information still needed. In a table, record expected behaviour, observed or simulated behaviour, evidence, risk and next step. At least one negative test must show how an unsafe request is denied or escalated.

:::warning Safe use
Never present cloud services as free or guaranteed to be available in every region.
:::

## Self-check and reflective feedback

What are the most relevant ownership, privacy and cost controls in the scenario? Explain how you would verify the result rather than assume success.
