# Module 1: From traditional IT to cloud computing

**Suggested time:** 45–70 minutes. **Competency:** The comparison correctly identifies service dependencies, organisational trade-offs and the limits of cloud availability.

## Concepts and architecture

A traditional IT deployment often buys and operates servers, storage and networks in a particular location. Cloud computing provides on-demand access to computing resources through managed services and metered commercial models. Resource pooling, rapid elasticity, measured service and self-service are common properties, but service quality varies by provider and plan. Distinguish public cloud, private cloud, hybrid cloud and multicloud: these describe organisational models, not security guarantees. Moving to cloud does not remove the need for architecture, data governance or business continuity. Edge computing may process data near devices when latency or connectivity matters.

## Workplace scenario

A fictional retailer runs its ordering system from an office desktop that fails during power outages. Decide which business functions could move to a managed cloud service and what remains dependent on local network connectivity.

## Applied exercise

1. Sketch a simple traditional architecture with a user, office router, server, storage, backup and support owner.
2. Sketch a cloud alternative identifying customer, provider region, service, identity, connectivity and shared responsibilities.
3. Compare benefits and constraints in five areas: cost, scalability, resilience, skill requirements and security.
4. Name two business needs where keeping a local or hybrid capability may be appropriate.
5. Explain how a lost internet link could still disrupt an otherwise healthy cloud service.
