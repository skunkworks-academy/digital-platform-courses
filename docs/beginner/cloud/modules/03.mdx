# Module 3: Regions, zones, networking and reliability

**Time:** 50–70 minutes. **Learning criterion:** The architecture distinguishes public pages and restricted data and does not expose administrative services.

## Understand the concepts

A cloud region is a geographic deployment area, while availability zones (where available) are separately engineered failure domains. Placement affects latency, law, service availability and disaster recovery. A virtual network contains subnets with defined address ranges; a route and firewall or security group control traffic. DNS resolves names and TLS can protect data in transit. A content delivery network can accelerate public content but should not be used to accidentally publish confidential records. Reliability requires measurement, tested recovery and avoiding unnecessary single points of failure.

## Workplace example

Learners in Africa and Europe access a training site. Its course pages may be cached publicly, but student identities and grades require protected storage.

## Guided practical activity

1. List four criteria for picking a primary region including residency, distance, price and service availability.
2. Draw browser, public site, authentication service, application API and restricted database.
3. Show which components may accept public inbound traffic and which must not.
4. Create one positive connection test and one unauthorised access denial test.

## Confirm the learning

The architecture distinguishes public pages and restricted data and does not expose administrative services. In a table, record expected behaviour, observed or simulated behaviour, evidence, risk and next step. At least one negative test must show how an unsafe request is denied or escalated.

:::warning Safe use
Do not open RDP, SSH or database ports to the entire Internet to simplify a lab.
:::
