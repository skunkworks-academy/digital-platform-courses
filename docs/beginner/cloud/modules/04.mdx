# Module 4: Identity, security and data protection in the cloud

**Suggested time:** 45–70 minutes. **Competency:** The controls use minimal access, protect sensitive data and provide explicit authorised and denied tests.

## Concepts and architecture

Identity is central to cloud security: use named accounts, multifactor authentication and least-privilege role assignments. Resource policies, network segmentation, managed identities and secret managers reduce risk. Encryption in transit commonly uses TLS; encryption at rest and key custody depend on chosen services and provider configuration. Backups, versioning and access logs must be configured and tested. The Zero Trust approach avoids assuming that a request is safe because it originated inside a network. Policies should fail closed; avoid embedding API secrets in repositories or URLs. A configuration screen showing encryption 'on' is not a substitute for access tests, key-recovery design and documented ownership.

## Workplace scenario

A developer wants to copy a cloud access key into JavaScript served by a public website. Explain how this exposes the key and design a safer service-to-service authorization arrangement.

## Applied exercise

1. Define a simple role matrix for student, course editor, support technician and administrator.
2. For each role, identify permitted actions and a prohibited action.
3. Design a multi-factor login and credential-recovery path for administrators.
4. Mark data classification and encryption requirements for course images, learner grades and billing records.
5. Write two negative tests: an anonymous student attempting to read grades and an unauthorised editor attempting to delete a database backup.

## Validation and reflection

The controls use minimal access, protect sensitive data and provide explicit authorised and denied tests. Create a verification register with **expected state**, **observed state**, **evidence**, **risk**, **owner** and **follow-up**. At least one test must demonstrate permitted activity and another must show an improper action is blocked or a faulty assumption is detected. Do not perform tests on systems without permission.
