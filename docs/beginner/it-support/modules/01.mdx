# Module 1: Computer components, operating systems and peripherals

**Estimated time:** 45–70 minutes. **Outcome:** A configuration record identifies the component affected and separates symptoms from likely root causes.

## Core concepts and why they matter

A computer combines processor, memory (RAM), persistent storage, network adapters and input/output devices. CPU handles instructions; RAM holds temporary working data; SSDs/HDDs store data persistently. A device's operating system coordinates hardware and applications; drivers translate between devices and OS. Distinguish a peripheral issue from a physical connector, software driver, power supply or application setting. Record device model, asset ID, operating-system version and user impact before recommending replacement.

## Worked workplace scenario

A laptop becomes slow when many browser tabs are open. The technician inspects memory pressure and process activity before proposing storage replacement.

## Guided hands-on application

1. Label CPU, RAM, SSD, adapter and peripheral in a simple diagram.
2. Explain the difference between available memory and free disk space.
3. Record a fictional device specification including OS version, update status, battery and display.
4. Choose two non-destructive tests for a missing printer.

## Verification and failure test

A configuration record identifies the component affected and separates symptoms from likely root causes. Create a table identifying expected result, actual result, date, supporting evidence and next action. Use one deliberately invalid or unexpected input to confirm the control does not silently fail.

:::warning Safety and ethics
Never open hardware or change BIOS settings in an owned business device without authorisation.
:::

## Extended learning: relate a symptom to a system component

A computer's **CPU** executes instructions, **RAM** holds active working data, and **storage** retains files and applications across restarts. The operating system coordinates devices and processes; drivers allow it to communicate with peripherals. Symptoms are not diagnoses: a slow application can result from storage pressure, network latency, insufficient RAM or a remote service issue.

### Worked example: “The computer is slow”

1. Ask when the problem started and whether it affects all programs or one task.
2. Record the operating system version, model, free storage, memory use and running applications using approved **read-only** tools.
3. Check power status, cables and peripheral connections before replacing components.
4. Compare an affected application with a known-good application or user workflow.
5. Identify the most likely layer, document what is still unknown and escalate changes requiring permission.

| Symptom | Initial hypothesis | Safer first check |
|---|---|---|
| No power indication | Power or charging issue | Approved outlet, adapter and indicator inspection |
| Frequent freezes | Resource, software or device problem | Resource graphs and event history |
| External display blank | Cable, display mode or port | Connection and display settings |
| Files unavailable | Permissions, sync or storage | Location and error message |

### Try it in a safe environment

Use your own computer to document five hardware/software characteristics **without changing settings**. Make a table with observed value, source and possible relevance to a support ticket.

**Think critically:** Why should an engineer confirm backup and authorisation before suggesting a factory reset? Describe what customer data could be lost and which tests should come first.
