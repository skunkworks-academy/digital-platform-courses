# Lab 3: Service desk incident simulation

**Duration:** 90 minutes. **Environment:** sandbox, owned device or paper simulation.

## Business scenario

Handle five fictional tickets, including a service outage, a routine request and an account security concern.

## Practical steps

1. Classify the tickets by incident/request and by priority.
2. Select ownership and first response for each case.
3. Write one user acknowledgement and one professional escalation.
4. Document a safe fix or a realistic workaround for every case.
5. Create an anonymised post-incident knowledge-base note and improvement recommendation.

## Evidence package

Five complete tickets, priority rationale, escalation notes and one publishable knowledge article. Include timestamp, expected state, actual state and a reflection on any discrepancies. Use fictitious cases; do not collect private credentials or customer records.

## Acceptance criteria

The learner communicates clearly, acts within permissions, and closes cases only when evidence meets user requirements.

## Troubleshooting challenge

Run a deliberately invalid or missing-input scenario, record the failure, determine the safest next step and retest after correction. Do not bypass controls or alter live systems for this exercise.
