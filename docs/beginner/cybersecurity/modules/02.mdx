# Module 2: Passwords, passkeys and multifactor authentication

**Estimated time:** 45–70 minutes. **Outcome:** Every fictional service has unique credentials and a recorded secondary sign-in/recovery method.

## Core concepts and why they matter

Account takeover frequently starts with reused passwords, stolen credentials or social engineering. Use a reputable password manager to create unique long passwords; never share a password through messaging. Multifactor authentication (MFA) combines distinct factors such as possession of a device and a passkey or verification method. Passkeys use asymmetric cryptography and are phishing-resistant when properly implemented. SMS codes are better than password-only but can be targeted by SIM-swap scams. Store recovery codes securely and review account recovery contacts.

## Worked workplace scenario

A simulated employee reuses the same password across three services. One service suffers a breach; an attacker attempts to reuse the credentials. The employee replaces passwords and enables appropriate MFA.

## Guided hands-on application

1. Create a fictional account inventory with five services and identify duplicate-password risks without revealing real passwords.
2. Select a password manager and define an evaluation checklist for encryption, recovery and device support.
3. Describe how to enrol a phishing-resistant sign-in method on an authorised test service.
4. Write an account-recovery checklist including emergency access, lost device and service-provider contact.

## Verification and failure test

Every fictional service has unique credentials and a recorded secondary sign-in/recovery method. Create a table identifying expected result, actual result, date, supporting evidence and next action. Use one deliberately invalid or unexpected input to confirm the control does not silently fail.

:::warning Safety and ethics
Never collect other learners' passwords, one-time codes, recovery codes or authentication seeds.
:::
