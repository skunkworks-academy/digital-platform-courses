# Module 5: Safe browsing, privacy and data handling

**Estimated time:** 45–70 minutes. **Outcome:** A data handling table defines purpose, owner, recipient, authorised location and review/removal date.

## Core concepts and why they matter

Protect personal data by collecting only what is required, using appropriate access rights, limiting unnecessary copies and sharing documents via authorised channels. Recognise secure connections but remember the padlock only confirms transport encryption—not website legitimacy. Browser extensions and mobile applications can have excessive privileges. Distinguish privacy settings, tracking consent, encrypted transport, data retention and deletion procedures. A zero-trust mindset continuously verifies identity, device and context before granting access.

## Worked workplace scenario

An employee wants to send a spreadsheet with fictional client addresses through an unapproved personal cloud drive. Explain a safer alternative using approved storage and access expiry.

## Guided hands-on application

1. Classify ten fictional fields as public, internal or restricted; explain the intended purpose.
2. Plan authorised file sharing with least privilege, an expiry date and a named recipient.
3. Check a sample browser extension's requested permissions and decide whether its access is proportionate.
4. Write safe-browsing rules for shortened links, unexpected downloads and sensitive data entry.

## Verification and failure test

A data handling table defines purpose, owner, recipient, authorised location and review/removal date. Create a table identifying expected result, actual result, date, supporting evidence and next action. Use one deliberately invalid or unexpected input to confirm the control does not silently fail.

:::warning Safety and ethics
Never conclude that a website is trustworthy solely because it uses HTTPS.
:::
