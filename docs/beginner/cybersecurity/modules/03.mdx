# Module 3: Detecting phishing, scams and malicious links

**Estimated time:** 45–70 minutes. **Outcome:** All dangerous examples are flagged without clicking links or opening attachments; a clear reporting path is recorded.

## Core concepts and why they matter

Phishing is a deceptive attempt to induce disclosure, payment, installation or account access through email, SMS, chat or phone. Recognise urgency, unexpected requests, spoofed display names, misleading domains, lookalike URLs, unusual attachments and demands to bypass procedure. Sender display names are not proof of origin. Hover or inspect a link safely but do not open a suspect link just to investigate. Contact a claimed sender through a separately known channel and report suspicious messages to the organisation's security contact.

## Worked workplace scenario

A fictional 'bank security' message asks a staff member to confirm a payment using a shortened link. A second message from a manager asks for gift cards. The student must decide safe responses.

## Guided hands-on application

1. Compare five invented messages and rate each as normal, suspicious or clearly unsafe.
2. For each suspicious example, identify at least two textual or contextual indicators.
3. Write a step-by-step safe verification response using an established contact number or official app.
4. Draft a short report containing received time, claimed sender, channel, observed indicators and protective action.

## Verification and failure test

All dangerous examples are flagged without clicking links or opening attachments; a clear reporting path is recorded. Create a table identifying expected result, actual result, date, supporting evidence and next action. Use one deliberately invalid or unexpected input to confirm the control does not silently fail.

:::warning Safety and ethics
A polished email with correct spelling can still be fraudulent. Context and independent verification matter.
:::
