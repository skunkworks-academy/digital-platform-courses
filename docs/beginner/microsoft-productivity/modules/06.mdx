# Module 6: Productivity workflows and quality control

**Study time:** 50–70 minutes. **Outcome:** apply this productivity capability using accurate, accessible and appropriately shared information.

## Learn the principles

Make repeatable templates for a weekly status report, meeting minutes and a workbook validation checklist. Workflows should preserve source documents, approvals and edit history. A useful KPI has a clear definition, data source, reporting period and owner. Automate only low-risk repeatable steps; maintain human checks for external messages, expense approvals or sensitive files. An Excel dashboard needs source tables, calculated metrics, descriptive labels and a documented refresh process.

## Worked business case

A training team wants to report enquiries, enrolments and attendance each week. Build a small workbook that calculates totals and conversion rate without including personal student records.

## Practical walkthrough

1. Design a weekly reporting checklist from incoming fictional rows to validated figures, chart and manager approval. Include one deliberate wrong input and show it is detected.
2. Capture the task objective, input data or document version, expected result and who will review it.
3. Produce a draft artefact or spreadsheet formula, then check one ordinary and one erroneous/unauthorised condition.
4. Correct the observed issue and preserve a simple change history.
5. Produce a short user-facing explanation of the final result and any outstanding limitation.

## Errors to avoid

A polished dashboard can still be wrong if its formula range omits new rows, if data was duplicated or if approvals were skipped.

## Knowledge and reflection checkpoint

- Which two checks must be performed before a document or calculation is shared?
- How would a colleague reproduce your work and detect a missing or incorrect value?

## Extended learning: develop a measurable productivity workflow

A reliable workflow defines the trigger, source, process, responsible person, quality gate, approved output and recovery procedure. Automation is useful only if it does not silently multiply errors. A quick spreadsheet does not replace source reconciliation or document approval.

### Worked example: produce a monthly training report

1. Receive a fictional CSV with course name, planned places and completed places.
2. Preserve the original and inspect missing or duplicated learner references.
3. Import cleaned records into a table, documenting any corrections.
4. Calculate totals and course completion rates using traceable formulas.
5. Draft a short Word summary distinguishing observed results from suggested causes.
6. Ask a designated reviewer to check arithmetic, source facts and file permissions.
7. Share the approved version and record its date, owner and storage location.

| Acceptance check | Evidence |
|---|---|
| Accuracy | Independent recalculation of a sample |
| Accessibility | Semantic headings and labelled tables or charts |
| Privacy | Restricted recipients and permitted data |
| Traceability | Source/version and change log |
| Accountability | Named reviewer authorises publication |

**Practice:** Draft a one-page standard operating procedure with one positive test and one deliberately invalid input. Include correction steps that preserve the original source and explain how a reviewer will confirm the final result.
