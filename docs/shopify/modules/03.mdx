# Catalog, Products and Merchandising

**Outcome:** Build a product model that supports customer decisions, inventory, fulfilment, search, accessibility, and reporting.

Define product types, vendors, tags, categories, options, variants, SKUs, barcodes, inventory policy, weights, fulfilment locations, costs, prices, compare-at prices, taxable status, and market availability. A SKU should be unique, stable, human-operable, and not encode volatile attributes.

Write titles for recognition and descriptions for decisions: intended use, material/specification, size/fit, compatibility, care, safety, contents, limitations, and delivery/return implications. Claims must be accurate and substantiated. Images need consistent framing, descriptive alt text, and sufficient resolution; avoid placing essential information only inside an image.

Collections group products manually or by rules. Build rules from governed fields so products do not appear unexpectedly. Navigation and search filters should use the customer’s vocabulary. Metafields/metaobjects hold structured reusable information such as specifications, ingredients, size charts, or care guides.

Inventory truth affects customer trust. Define whether overselling/backorders are permitted, which location fulfils, safety stock, cycle counts, damaged/returned stock treatment, and reconciliation ownership.
