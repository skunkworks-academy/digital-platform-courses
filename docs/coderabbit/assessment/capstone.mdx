# CodeRabbit Capstone — Review System Design

## Scenario

A team wants faster reviews for a service containing authentication, payments, database migrations, generated API clients, and documentation. They have experienced noisy AI comments and one missed authorization defect.

## Deliverables

1. A scope, privacy, permission, ownership, incident, and removal decision record.
2. A valid `.coderabbit.yaml` with justified profile, trigger policy, exclusions, and path-specific instructions.
3. A GitHub merge-control diagram separating deterministic, CodeRabbit, human, security, and emergency decisions.
4. A sample PR with at least three findings; triage and verify each disposition.
5. One implemented regression test and verified fix.
6. A response to a false positive that preserves respectful audit evidence.
7. A six-metric dashboard definition with baselines, owners, review frequency, and unwanted incentives.
8. A 30-day tuning experiment and rollback condition.

Estimated effort: 75 minutes. Use synthetic code/data. Declare assistance and submit a redacted criterion-to-evidence index.
